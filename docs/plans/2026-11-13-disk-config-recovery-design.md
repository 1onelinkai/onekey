# 重装后识别现有模型配置

问题：概览卡片只使用 OneLinkAI 配置历史构造已配置状态，应用数据或历史丢失后，客户端仍有配置却显示未配置。

实现：复用配置检查器的用户级文件路径、格式解析和脱敏策略，在检测时生成只含模型 ID、默认模型、数量和读取状态的摘要。卡片及配置弹窗默认模型使用此摘要，不再将历史写入记录作为当前磁盘状态。写入或恢复后重新检测。历史与备份保持独立，不伪造恢复记录。

模型注册列表不能证明当前会话使用哪一个模型。后续补充读取 WorkBuddy、VS Code、ZCode 的本地选择记录及 OpenCode 最近使用项，区分默认项和上次选择；仍无法确定时展示模型数量并说明原因。详见 2026-11-13-model-selection-detection.md。配置解析失败单独显示无法读取。项目级配置、运行参数和客户端会话可能覆盖用户级默认值。

验证：创建 16 种客户端配置，再使用全新 OneLinkAI 数据目录，确认无历史时能识别模型。补充外部修改、文件损坏、删除、多个模型无默认值、Windows 路径与本地覆盖优先级检查；Electron 配置流程通过。
