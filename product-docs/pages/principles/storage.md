# 凭据与本地数据

## 先区分三种密钥

**平台登录令牌**证明你在 OneLinkAI 平台的身份；**模型 API Key**允许向模型服务商发请求；**本地加密密钥**用于解开电脑里的密文文件。三者不能互换。

## 当前真实保存方式

| 数据 | 当前桌面保存方式 | 是否跨重启 | 是否自动访问系统钥匙串 |
| --- | --- | --- | --- |
| 平台登录 token / refresh token | `userData/platform/session.local.enc` | 是 | 否 |
| BYOK 服务商 Key、资料、模型、默认选择 | `userData/local-providers/session.local.enc` | 是 | 否 |
| 各自的加密密钥 | 同目录 `session.local.key` | 是 | 否 |
| 平台 Key 列表缓存 | 主进程 Map | 否，重新向平台取 | 否 |
| 配置预览中的真实 Key | 主进程计划 Map | 否，10 分钟有效 | 否 |
| 写给 Agent 的密钥 | 取决于原生配置格式；很多是明文 | 是 | Zed / VS Code 由用户手动在目标应用保存 |
| 配置原始备份 | `agent-config/backups/<操作ID>/<序号>.bak` | 是 | 否 |

服务商密文文件名仍叫 `session.local.enc`，是因为复用了同一个存储实现；它与 platform 目录中的文件相互独立，不会因为名称相同混为一份。

## 加密格式与写入过程

`createSessionStore()` 首次保存时创建随机 32 字节密钥，文件使用独占创建避免覆盖已有 Key。加密采用 AES-256-GCM，每次生成随机 12 字节 nonce，使用 `OLS1` 作为认证附加数据。

```text
密文文件 = OLS1（4 字节）
         + nonce（12 字节）
         + GCM authentication tag（16 字节）
         + 加密后的 JSON 文档
```

保存到独立临时文件，再 rename 替换目标；目录以 0700、文件以 0600 创建。权限数值主要描述 POSIX 行为，不能等同于 Windows 完整 ACL 配置。解密会验证格式、密钥长度和 GCM tag；密文损坏或 Key 不符不会被当作空列表静默重置。

## 本地加密能保护什么

磁盘上不会直接出现明文登录令牌或明文服务商文档，普通文件误览不会直接展示 Key。但加密密钥也存在同一用户可读的本地目录中：**拿到密文和 Key、或已经能以你的账户读取二者的程序，可以解密。**

这不是硬件密钥保护，也不等价于钥匙串或独立主密码。当前方案优先满足“不调用钥匙串、不弹授权、跨启动恢复”的产品行为。不要把整个 userData 打包公开。

## Agent 配置为什么仍可能有明文

目标客户端需要按自己的格式读取凭据。Claude Code 的 env、Codex 的 bearer token、WorkBuddy 的 apiKey、Gemini 的 `.env` 等都可能包含实际 Key；本地服务商存储加密不会自动让这些原生格式也变成加密格式。

备份保留原始文件字节，因此 `.bak` 也可能含旧密钥。配置查看器脱敏，不代表原文件或原始备份已加密。分享日志、备份和截图时应按具体内容处理。

## Zed 与 VS Code 的特殊路径

生产主进程创建 Agent 服务时不注入系统 credentials 对象。Zed 当前只写模型定义，提示到 Zed 手动填 Key；VS Code 当前只写模型定义，提示在 VS Code 管理模型中保存 Key。

仓库保留旧 `credentials.cjs`、`credential-storage.cjs` 以及可注入 credentials 的测试分支。文件存在不等于生产启动正在调用它们；不能据此把当前行为写成自动访问钥匙串。

## 删除与迁移

退出平台登录只清会话密文及内存缓存；`session.local.key` 保留，BYOK 和 Agent 配置也保留。删除 BYOK 服务商只修改服务商存储，不吊销远端 Key、不清理 Agent 文件。

当前没有一键导入导出全部加密数据的产品功能，也没有通用的旧钥匙串密文静默迁移入口。需要离线备份时应同时保留对应目录中的密文与 Key，并保管为敏感数据；只复制密文通常无法在另一目录恢复。

## 多实例与数据一致性

服务商编辑在同一 store 实例内串行，但不同进程之间没有文件锁；同时打开两个工作台编辑同一 userData 可能读到旧快照并覆盖。避免并发运行多份。临时文件替换保证单个文件替换的完整性，不是跨多个进程的数据库事务。
