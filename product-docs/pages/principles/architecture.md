# 整体架构与数据流

## 一次操作经过的四层

```text
React 工作台页面（展示、输入、交互状态）
       ↓ 白名单函数调用
preload 暴露的 onelinkDesktop 桥接
       ↓ onelink:* IPC
Electron 主进程（验证来源、取凭据、生成计划）
       ├─ 本机文件：Agent 配置 / 本地加密数据 / 历史备份
       ├─ 子进程：版本命令 / npm / 官方安装器 / 系统工具
       └─ 网络：平台 API / 服务商模型接口 / 版本及下载源
```

## 页面为什么不能随意读取电脑

主窗口配置 `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`、`webSecurity: true`。预加载脚本提供有限函数，页面不能直接导入 Node 的 fs 并任意执行命令。

主进程处理 `onelink:*` 时验证 IPC 发送框架是否来自可信工作台页面。正常构建页面还设置 CSP，限制脚本与资源来源；开发 URL 使用另一条开发加载路径。

浏览器权限请求默认拒绝，新窗口及外部链接经过控制。这些是当前隔离措施，不构成对所有 Electron 漏洞和本机恶意软件的绝对防御。

## 平台 Key 配置的数据流

切换下面的来源，再选择步骤，查看这一刻的数据放在哪里、由谁发送请求。

<FlowExplorer />

```text
用户选组织和 Key → 主进程重新取 Key 详情并验证状态
→ 选择模型、Agent 和协议 → 适配器生成带真实凭据的内部计划
→ 页面仅见脱敏预览 → 用户确认令牌 → 备份、写入、回读
→ Agent 重启后按自己的配置向平台地址发请求
```

## BYOK 配置的数据流

```text
用户输入服务商 Key → 本地加密保存
→ 主进程解密并取所选启用模型 → 可选拉取模型 / 测试连接
→ 相同的适配器预览与写入流程
→ Agent 向填写的服务商直接请求
```

工作台不会在每次 Agent 对话时持续为它注入密钥；文件写完后，Agent 根据自己的规则读取。手动填密钥的 Zed、VS Code 走目标应用自己的凭据路径。

## 配置中为什么出现 OneLinkAI

`onelinkai` 是多数适配器采用的 provider 标识或分组名，方便区分工作台管理的节点。它不代表所有请求强制走 OneLinkAI 平台。真正决定请求目的地的是对应节点里的 `base_url/baseURL/api_url/url`。

同一节点再次配置时，部分适配器替换整个 OneLinkAI provider，部分按模型 ID 合并。详见[逐 Agent 参考](/reference/agents/)。

## 运行时状态和磁盘状态

| 状态 | 生命周期 |
| --- | --- |
| 页面输入、模型选择弹窗、提示消息 | 窗口页面生命周期 |
| 平台 Key 缓存、预览计划、安装日志、正在执行任务 | 主进程生命周期 |
| 平台登录会话、BYOK 服务商 | 本地加密文件跨进程保存 |
| Agent 配置、配置历史、备份 | 本地文件跨进程保存 |
| 模型推理和平台日志 | 由目标服务商 / 平台实际请求决定 |

## 网络栈并非完全相同

主进程中有 Electron `net.fetch`，也有 Node 全局 `fetch`；安装还会创建携带代理环境的外部进程。不能保证“某一条下载成功”就代表平台登录、连接测试和所有外部命令都走了完全相同的代理。

安装流程对 SOCKS 场景创建的本机桥接仅用于该安装的网络适配，不是统一的模型 API 中转服务。
