# 常见问题与术语

## 不登录能用吗？

可以，BYOK 不依赖平台登录。平台组织、Key、钱包和请求日志需要登录。

## BYOK 数据会同步到平台吗？

当前服务商资料保存在本机，没有云同步功能。拉模型和测试会按用户填写的地址请求服务商，之后目标 Agent 的实际对话也由其地址决定。工作台页面中的平台日志不会自动收集独立第三方服务商的请求。

## 本机模型服务能接吗？

地址校验允许 localhost、127.0.0.1、IPv6回环的HTTP，仍需协议和目标Agent兼容。当前服务商 Key 字段至少8字符；即使本机服务不需要认证，表单也没有专门“无 Key”模式，不能假定空密钥能保存。

## “默认模型”会改所有 Agent 吗？

不会，它是下一次选择配置的偏好。实际写哪个 Agent 需要用户执行对应配置；不同应用里的默认值各自存在。

## 删除服务商后，Agent 为什么还能用？

密钥和地址此前已写入 Agent 文件。删本地资料不等于吊销服务商 Key；要撤销权限应到提供方停用 Key，并重新配置本机应用。

## 为什么同样的模型有名字和 ID 两个字段？

名字是给人看的，ID是发请求和生成配置用的标识。修改显示名不应该让API去请求不存在的模型；不同适配器对显示名的支持也不同。

## 能否保证所有客户端都能一次自动配完？

不能。Zed、VS Code需要用户在目标应用内保存Key；某些客户端要选择Profile或模型，部分高级字段未开放映射。每个Agent页明确写出这一步。

## 仅关闭窗口算退出吗？

通常不算，程序隐藏到状态栏，主进程与任务可能继续。完全退出才会结束内存计划和缓存。本地服务商及登录文件仍保留。

## 复制脱敏配置可以拿去恢复吗？

不适合。查看器重新格式化并去掉秘密及注释，复制的是说明文本；恢复依赖原始备份和历史记录，或你自己保管的原始文件。

## 有没有“检测出新版自动帮我升级”？

当前只有后台自动查询，更新需要用户确认执行。发现新版本与允许管理当前来源是两件事。

## 术语表

| 术语 | 在本文中的意思 |
| --- | --- |
| Agent / 客户端 | Claude Code、Codex、WorkBuddy等第三方程序 |
| Provider / 服务商 | 地址、协议、Key和模型的组合；原生配置也常叫provider |
| BYOK | Bring Your Own Key，使用自己的模型密钥 |
| API根地址 | 追加协议路径之前的基础地址 |
| Protocol / 协议 | Chat Completions、Responses、Messages、Gemini原生等请求/响应规范 |
| Token（登录） | 平台身份凭据，与模型token计量不是同一意思 |
| Token（模型） | 模型上下文和输出的计量单位 |
| IPC | Electron页面与主进程间受控调用通道 |
| userData | Electron本地应用数据目录 |
| Shim | 把命令转发到实际程序的薄包装入口 |
| Prefix | npm独立安装根目录 |
| Profile | 目标应用的一套配置空间，可能有多份 |
| Cask | Homebrew桌面应用元数据；查询它不代表通过brew执行安装 |
| Dist-tag | npm发布者维护的版本标签，如latest、next |
| Semver | 语义版本的解析与比较规则 |
| 原子替换 | 先写临时文件再rename，减少读到半文件；不是跨多文件数据库事务 |
| 回读校验 | 写后读文件计算哈希，证明内容与计划一致 |
| 回滚 | 当前操作失败，尝试撤销已完成部分 |
| 历史恢复 | 对一条过去成功配置执行还原，须确认之后未被修改 |
