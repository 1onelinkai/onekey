# 故障排查

按“数据是否在、路径是否对、格式是否对、实际请求是否对”的顺序定位，避免反复覆盖还没看清的文件。

## 重启后服务商 / 模型不见了

1. 确认是否真的保存并看到“已保存”，而非只填写表单或在模型弹窗未确认。
2. 检查是否运行当前修复后的桌面版，完全退出旧主进程再打开。单纯刷新页面不会替换主进程代码。
3. 核对运行方式及 userData：开发版与发行版可能使用不同目录；在不同目录启动测试隔离版也不会读取原列表。
4. 核对 `local-providers/session.local.enc` 和 `session.local.key` 是否都存在。不要公开其内容或随意删 Key。
5. 查看页面错误。解密失败与真正空列表是不同情况；文件损坏不要用新空文件先覆盖原件。
6. 避免多份工作台并发编辑同一文件。

旧版仅在内存中的服务商在进程结束后无法从磁盘恢复。当前持久化不能逆向找回此前从未保存的资料。可先使用虚构服务商做“保存 → 完全退出 → 重启”的小验证，再填真实资料。

## 每次重启都要登录

当前登录保存到 platform 目录。如果只关闭官网登录窗未完成 SSO、刷新令牌被服务端吊销、加密 Key 缺失、运行在另一 userData 或应用数据被清理，会需要登录。

有本地 token 时界面可能先显示已登录，随后网络401且刷新失败再退出；这不同于程序完全没有保存。检查平台是否主动使会话失效。

## 我安装了 Agent，但卡片显示未安装

查看卡片证据和命令真实路径。配置目录存在不代表程序存在；新的终端 PATH 和从 Finder 启动的进程 PATH 可能不同。检测不会执行完整 shell 启动脚本，也不扫描自定义任意目录。

安装后重新打开终端并重扫。不要为了让卡片变绿直接创建一个同名假文件，它可能让后续来源判断失真。

## 卡片版本与终端不一样

通常是多份安装。托管 bin 优先，macOS 某些桌面版本从 Info.plist 读，终端可能命中另一个 CLI。核对 `executable`、`bundle` 和原安装渠道，先决定要管理哪份。

## “版本暂未查到”

打开信息提示查看失败原因和查询源。可能是网络、代理、速率限制、上游结构变化、包名渠道不可达、元数据缺哈希或本机版本不可解析。等后台重试即可；不是升级已执行失败。

## “有新版本 · 原渠道更新”

发布版本比本机高，但当前安装位置未匹配允许自动更新来源。使用客户端内置更新、原 npm 或 Homebrew 工具，不应把系统管理的文件直接移动进托管目录冒充来源。

## 安装卡住或失败

查看当前阶段和最近日志：源码、依赖、下载、解压、PATH、版本验证对应不同问题。没有日志输出不一定等于死锁，部分依赖阶段较慢，但代码有总阶段超时。

先看磁盘、用户目录写权限、网络与代理、Git依赖、系统/架构要求。线路响应延迟只测元数据，不证明大文件下载带宽。全部线路失败不会自动降为另一个未经固定的包版本。

退出应用可能终止任务；下次不是完整事务续跑。桌面包可缓存续传，其他任务仍应重新检查实际状态。

## 提示“配置已被其他程序修改”

预览之后目标文件发生了变化，工作台主动拒绝旧计划。重新读取、核对并重新预览。不要只重复点击旧确认按钮，令牌是一次性的。

## 恢复提示“写入后已变化”

当前文件不再等于历史写后哈希。可能是你或 Agent 后续编辑，也可能是更晚的一次配置。先查看当前文件与备份，在本地编辑器比较；需要自动恢复时一般按最近相关记录向前处理。

原始备份可能含明文 Key，只在本地检查，分享时先脱敏。缺失备份时不要承诺自动恢复。

## 模型列表能拉，测试却失败

分别检查根地址、协议、模型 ID、Key 权限、额度、网络与服务商最小参数要求。模型列表只是目录接口，不保证每个 ID 有推理权。简单测试的小输出参数也可能被个别模型拒绝。

HTTP 401/403 常见认证 / 权限问题，404 常见路径 / 模型问题，429 常见限流或额度问题，5xx 常见上游服务问题；这些只是排查线索，不是替服务商定义错误的最终规则。

## 测试成功，Agent 仍然不工作

确认：完成写入了吗？用的是新会话吗？Agent是否读取同一个配置目录？Zed / VS Code 是否补了 Key？使用正确 Profile 吗？有没有项目 `.env`、环境变量或命令行覆盖？

还要区分测试只发短文本，而目标 Agent 可能要求流式、工具、图片或更大的输出。查看目标 Agent 实际报错和服务商日志，不要用“测试成功”代替这些检查。

## 看到钥匙串 / 系统授权窗口

工作台当前登录和 BYOK 不访问钥匙串。Zed / VS Code 内用户保存凭据时，可能由它们自己触发系统密钥存储行为；某些第三方程序安装脚本也有自己的凭据依赖。

macOS 外部 npm 卸载可能因目录权限触发管理员授权，这与钥匙串不同。核对窗口标题、触发动作和目标程序，不要用旧 README 的钥匙串描述判断当前接线。

## macOS 无法启动应用

正式包可能由原生启动器显示早期错误，支持复制详情，日志路径见[本地路径](/reference/paths-network)。若系统在启动器运行前就拒绝应用，内部也可能无法写报告；需要结合安装包来源、签名与系统错误排查，不能仅以开发机能打开说明所有机器都修复。

分享反馈时提供版本、系统、芯片、启动方式、触发步骤和脱敏错误；不要发送真实 Key、session.local.key 或完整未脱敏 userData。
