# BYOK 与模型管理

BYOK（Bring Your Own Key）指使用自己已有的服务商密钥。平台登录、组织和平台额度都不是 BYOK 的前置条件。

## 服务商资料包含什么

| 字段 | 含义与当前校验 |
| --- | --- |
| 名称 | 必填，去首尾空格，最长 100 字符 |
| 接口地址 | 必填根地址，HTTPS；仅 localhost、127.0.0.1、IPv6 本机回环允许 HTTP；不允许 URL 用户名密码、查询参数或片段 |
| 接口协议 | `openai`、`responses`、`anthropic`、`gemini` 四选一 |
| API Key | 8–2048 字符，不允许换行和空字符；编辑时留空保留原 Key |
| 备注 | 可选，最长 1000 字符 |
| 官网链接 | 可选，仅 HTTPS，不能包含 URL 用户名密码；点击时再次校验 |

保存服务商本身不请求推理接口。地址结尾斜线和常见 `/v1` 会归一化；Gemini 创建时还处理 `/v1beta`。不要依赖它去解析任意完整 API 路径。更改协议后请重新核对根地址。

## 保存到哪里，谁可以看见

当前桌面版将整个服务商文档加密存入 `userData/local-providers/session.local.enc`。密钥在同目录 `session.local.key`。列表 IPC 仅返回服务商公开资料与模型，不包含 API Key。

密钥用于拉取模型、连接测试及生成配置时才由主进程解密使用。BYOK 表单输入 Key 的当时，输入自然存在于页面状态；保存完成后表单清空，列表不会再次回传完整 Key。

这是本机磁盘持久化，并非仅进程内存。没有云端同步，也没有组织级 BYOK 分区。两份文件的保护能力与限制见[凭据说明](/principles/storage)。

## 一键拉取的完整过程

点击后先打开模型选择弹窗。弹窗异步向服务商取列表，协议决定端点与请求头：

| 协议 | 列表路径 | 认证方式 |
| --- | --- | --- |
| Chat Completions / Responses | `/v1/models` | Bearer Key |
| Anthropic Messages | `/v1/models` | `x-api-key` 与 `anthropic-version: 2023-06-01` |
| Gemini | `/v1beta/models` | `x-goog-api-key` |

列表请求禁止重定向，整次分页共用 20 秒超时。Anthropic 用 `after_id/last_id/has_more`，Gemini 用 `pageToken/nextPageToken`，最多 100 页并拒绝循环游标；普通 OpenAI 兼容列表目前只取返回的那一页，不支持所有厂商的自定义分页规则。

Gemini 列表会排除明确不支持 `generateContent` 的条目，并去掉 ID 开头的 `models/`。无效响应或 ID 会报错，不把部分结果静默保存。

## 搜索与分类代表什么

搜索对 ID 和名称做不区分大小写的子串匹配。分类由名称和 ID 的关键词推断为对话、视觉、图像、语音、视频、向量、重排序，不是服务商认证的能力标签，也不是实际推理测试。

例如带 `embed` 的名字通常归为向量，但“对话”分类不保证具备工具调用。选择框里能出现嵌入或图像模型，不意味着所有编程 Agent 都能使用它。

## 勾选、取消和已有资料

模型列表合并远端结果与已有模型，避免一次远端缺项就直接抹掉本地模型。已有模型默认勾选；选择仅保存在弹窗内存，点击取消不修改存储。

“全选当前结果”和“取消当前结果”仅影响当前搜索及分类下可见的条目。确认时，主进程验证完整选择列表，一次性替换该服务商的模型集合：

- 勾选的新 ID 加入，默认启用；
- 取消勾选的旧 ID 删除；
- 保留的旧 ID 继续使用原名称、规格、启用状态和默认标记；
- 被删除的默认模型会清空默认选择；
- 重复 ID、非法 ID、超过 10000 个条目会被拒绝，验证失败不写入。

选择模型不会删除服务商远端的模型，也不会批量修改已经配置的 Agent。

## 手动模型与共用规格

没有列表接口或某个模型没在列表里时，可以手动添加准确请求 ID。模型显示名称可以与 ID 不同。上下文、最大输出、图片、工具、推理等字段是用户维护的能力声明，拉取不自动推断这些规格。

ID 校验支持字母数字及 `_ . / : @ + -`，最长 200 字符；当前写配置的通用校验不接受 `@`，因此个别可存储的 ID 仍可能在配置时被拒绝，这属于当前实现差异。

停用模型会阻止后续选用；停用默认模型会清空默认。删除模型、服务商或更换 Key 均不自动回收已写到 Agent 的旧配置，需要重新配置各目标。

## “默认模型”不是强制同步开关

默认模型为后续配置提供优先选择，不会自动改动所有应用。不同服务商的相同模型 ID 由 providerId 区分。操作串行排队，避免同一进程并发修改丢失数据；当前没有跨多个 Electron 进程的文件事务锁，应避免同时运行多份工作台并修改同一套数据。
