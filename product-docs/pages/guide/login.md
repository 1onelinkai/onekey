# 登录、组织与平台 Key

登录是为了读取 OneLinkAI 平台上的组织、密钥、额度和请求记录。BYOK 不需要这一步。

## 登录窗口实际做了什么

1. 用户主动点击登录，主进程打开独立登录窗口，进入官网 `/Login`。
2. 窗口使用名为 `onelink-login` 的独立会话分区，不是带 `persist:` 的磁盘分区；网页 Cookie 与工作台隔离。
3. 页面、弹窗和重定向仅允许代码列出的 HTTPS 域名，包括 OneLinkAI 及部分第三方登录域名；其他导航会被阻止。列入允许域名不代表每种第三方账号流程都已完整验收。
4. 主进程通过该登录窗口的 Chromium 调试协议，观察 **本次窗口**向 `/sso/client/token` 发出的 POST 成功响应。只接收顶层页面为 OneLinkAI 官网时的结果。
5. 恢复响应继续交给官网后，将 access token 和 refresh token 交给平台服务验证。
6. 调用 `/sso/client/getUserInfo`，确认账号有效且有 userId，才保存会话并关闭登录窗口。

此流程没有扫描其他浏览器历史或从其他应用窃取登录态。捕获范围固定在用户操作的隔离窗口及特定 SSO 响应。

## 重启后为什么还能登录

会话对象包括 access token、refresh token 和用户资料。当前桌面接线将它交给本地文件加密存储，保存在 `userData/platform/session.local.enc`，加密密钥为同目录的 `session.local.key`。

应用启动时按需加载会话。`status()` 当前依据本地是否存在 access token 展示登录状态，不代表已经向服务器再次验证有效期。之后的平台请求若返回 HTTP 401，才进入刷新流程。

## Token 刷新规则

普通平台请求携带 `Authorization: Bearer …`。第一次遇到 401 时，使用 refresh token 请求 `/sso/client/refreshToken`，保存新令牌，然后重试原请求一次。

并发请求共享一个刷新任务，避免重复刷新。刷新失败会清除当前登录会话；没有 refresh token 时需要重新登录。登录、退出造成会话代次变化后，旧请求结果被拒绝，避免写回另一账号的数据。

## 组织如何隔离

组织列表由 `/user/user/userTenantList` 返回，并在前面加入个人工作空间。个人范围用 `tenantType: 1`；组织范围用 `tenantType: 2`，附 tenantId 和管理员标记。

界面切换组织会清空当前 Key、额度和日志状态，并发起新请求。前端请求代次与主进程的范围检查共同避免旧组织结果误用；真正的数据访问授权仍由服务端执行。

## 平台 Key 的读取与展示

列表请求分页，每页 100 条、最多 100 页；界面得到名称、脱敏值和状态信息。原始记录在主进程内存中缓存，不在渲染页面展示完整密钥。

配置或拉模型时，主进程再次调用 Key 详情接口，验证停用、过期和预算状态，并取完整密钥。含星号、圆点或空白的值不被当作完整凭据。服务端若只提供脱敏值，工作台会明确拒绝配置。

平台 Key 与登录会话不是同一种存储：登录令牌需要跨启动保存；Key 列表及其完整记录缓存随进程退出消失，之后由平台重新获取。

## 退出登录会删除什么

删除登录会话密文文件，清空内存 Key 与组织列表，清理独立官网登录窗口的网页存储。加密密钥文件会保留。

退出登录不会撤销已经写进 Agent 的 API Key，也不会删除 BYOK 服务商或配置备份。要停用已经分发的 Key，应到平台撤销或轮换，并更新目标 Agent 配置。

## 取消、失败与重试

关闭未完成的登录窗口会返回“已取消登录”。网络失败、SSO 格式变化、域名不在允许列表、账号验证失败都可能中止接入。登录重入会复用正在进行的窗口，而不是创建多套并发接入。

实现依据：`electron/platform-login.cjs` 的 `login/logout`、`electron/platform-live.cjs` 的 `acceptSession/status/call/refresh/scope`。
