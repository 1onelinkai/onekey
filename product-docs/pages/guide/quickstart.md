# 完成第一次配置

## 1. 使用桌面版

通过 Electron 启动的 OneLinkAI 才有本机文件、程序检测和安装能力。单独运行的网页预览只展示界面，不能代替桌面版完成配置。

关闭窗口通常只是隐藏到状态栏；需要完全退出时使用状态栏的“退出 OneLinkAI”或系统退出命令。修改主进程代码后，仅刷新界面不会替换仍在运行的主进程。

## 2. 检查客户端是否已安装

首页查看 Agent 卡片。已安装卡片展示检测到的版本和安装证据；没有找到时切换“全部”，查看是否能一键安装，或按安装说明使用原渠道安装。

“检测到”只证明存在程序或应用包，不能证明账号、Key、模型或 API 连通。

## 3. 选择一种模型来源

### 使用平台 Key

主动登录 OneLinkAI，选择组织，在 API Keys 页选择可用 Key，然后打开“配置”。平台没有返回完整密钥时，工作台会拒绝生成凭据配置，而不会把脱敏字符写到 Agent。

### 使用 BYOK

进入“模型服务商”，填写名称、接口根地址、协议和 API Key，点击保存。随后手动添加模型，或点击“一键拉取模型”。在弹窗中搜索、分类和勾选，再确认选择。仅拉取不会把全部模型自动加入。

示例地址使用 `https://api.example.com`。不要填完整的 `/v1/chat/completions` 请求路径，详见[地址规则](/principles/protocols)。

## 4. 选择 Agent、模型和协议

配置面板中的协议必须与 Agent 适配器匹配。例如 Codex 使用 Responses，Claude Code 使用 Anthropic Messages，Gemini CLI 使用 Gemini 原生协议。模型名字类似，并不代表协议相同。

高级设置只填真实支持且需要覆盖的参数。不确定上下文与输出上限时，先保留默认设置，再阅读该 Agent 页。

## 5. 测试连接和预览

连接测试会发起一条很小的真实推理请求，可能计费。预览本身只生成计划，不写磁盘；你可以检查即将修改的文件、示例字段及手动操作说明。

看到 `<API_KEY>` 或 `<REDACTED>` 是展示脱敏，真正写入的凭据由主进程持有。不要把示例占位符当成可用密钥。

## 6. 确认写入

提交后工作台检查原文件未变化、保存原始备份、按顺序写入并回读校验。显示文件写入成功，表示磁盘内容符合本次计划。

| 目标 | 写入后还要做什么 |
| --- | --- |
| Zed | 在 Zed 模型设置里手动填写 API Key |
| VS Code | 在管理模型中为 OneLinkAI / Custom Endpoint 保存 API Key，使用默认 Profile，或另配其他 Profile |
| Claude Desktop | 完全退出重启，按提示选择 OneLinkAI 第三方网关配置 |
| WorkBuddy、ZCode | 重启后在应用内选择 OneLinkAI 模型 |
| DSH | 使用本次配置的 desktop profile；其他 profile 单独设置 |
| 其他客户端 | 重启或新建会话；旧进程可能继续使用旧参数 |

## 7. 核对结果或恢复

用目标 Agent 发出一次实际请求，核对服务地址、模型 ID 和响应。失败时先查协议和覆盖来源，避免连续盲目重写。

需要撤销时进入“配置记录”恢复对应操作。只有目标文件仍与当次写入结果一致时，才会自动恢复；后续手动编辑过会阻止恢复，以保护新修改。
