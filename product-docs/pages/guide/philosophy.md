# 产品理念与边界

OneLinkAI Desktop 是一个本机 Agent 配置与管理工作台：集中选择模型来源，再把地址、模型和必要凭据转换成各客户端认识的配置。

## 为什么需要一个工作台

多个 Agent 会把同样的信息放在不同位置。一个使用 JSON 的环境变量，一个使用 TOML 的 provider，一个把模型定义与凭据分开；即使都叫“OpenAI 兼容”，也可能分别要求 Chat Completions 和 Responses。

工作台解决这些重复工作：发现本机客户端、识别安装来源、维护服务商与模型资料、生成原生配置、保存变更历史，并在条件明确时安装、升级和卸载程序。

## 三个设计原则

### 本地配置，交还给原生客户端运行

OneLinkAI 负责写入配置，不接管 Agent 的对话界面、项目目录、工具权限或会话运行。配置完成后，实际模型调用通常由 Agent 直接发往写入的服务地址。当前应用没有为所有 Agent 建立常驻的本地模型转发服务器。

### 共享信息，保留各客户端的差异

服务商地址、模型 ID、显示名、上下文等可以复用，但适配器只写已实现且被当前能力表允许的字段。界面显示“未写入”的参数不会通过一个虚构的通用字段强行塞给客户端。

### 每次修改尽量可解释、可恢复

预览说明目标文件，提交前检测外部修改，落盘前备份，落盘后回读校验。能自动恢复时恢复；无法保证不覆盖后续修改时，停止自动恢复并提示手工处理。

## 两条模型来源

| 来源 | 适合谁 | 登录要求 | 请求最终发往 |
| --- | --- | --- | --- |
| OneLinkAI 平台 Key | 使用平台的组织、额度和模型授权 | 需要平台账号 | 配置中的平台 API 地址 |
| BYOK 本地服务商 | 已持有其他服务商 Key 或本机服务 | 无需 OneLinkAI 登录 | 用户填写的服务商地址 |

BYOK 的提供方资料没有按当前组织 ID 分区；切换平台组织不会为 BYOK 自动建立另一套隔离空间。

## 当前不承担的工作

不创建、删除平台 API Key；不读取所有应用的系统凭据；不自动修改项目级配置；不保证第三方 Agent 每次升级后配置格式都不变；不把测试请求成功视为所有工具调用、图片、流式、长上下文都通过验收。

文档中的“自动检测更新”指 Agent 版本检测。当前 OneLinkAI 自身没有接入完整的应用内自动下载安装更新流程；安装包签名与公证是另一项分发能力。

## 右上角的“本机服务可用”意味着什么

它目前由网页是否拿到 Electron 的本机能力桥接对象判断。它不是每个 Agent 的健康检测，也不是所有服务商都在线、平台登录有效或后台模型服务已启动的证明。界面只保留这一个位置展示，避免重复。
